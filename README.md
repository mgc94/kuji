# 행운의 뽑기 — GitHub / Netlify 업로드용

## 구성
- 티켓 10열 × 10행, 총 100장
- 1등 1장 / 2등 3장 / 3등 10장 / 4등 30장 / 5등 56장
- 매 새 뽑기판 시작 시 전체 등수를 무작위로 섞어 티켓에 배정
- 티켓 선택 → 뽑기 시작 → 쿠폰 열기 → 당첨 등수 확인
- 랜덤 선택, 남은 상품 수량, 최근 10회 결과, 전체 화면
- 이미 뽑은 티켓은 다시 선택 불가
- 새로고침 후에도 같은 브라우저에서 이어서 진행
- 쿠폰을 열기 전 새로고침해도 확정된 티켓을 다시 보여줌

## GitHub에 올리기
1. ZIP 압축을 풉니다.
2. 새 GitHub 저장소를 만들고 **Add file → Upload files**를 선택합니다.
3. `netlify.toml`, `README.md`, `public` 폴더를 저장소 최상위에 올립니다.
   ZIP 파일 자체나 바깥쪽 `kuji-site` 폴더를 올리지 않습니다.
4. 저장소 최상위에 `netlify.toml`과 `public` 폴더가 보이는지 확인하고 Commit합니다.

## Netlify에서 GitHub Import
해당 GitHub 저장소를 선택합니다. 아래 설정을 사용하세요.

| 설정 | 값 |
|---|---|
| Base directory | 비워두기 |
| Build command | 비워두기 |
| Publish directory | `public` |

`netlify.toml`에도 Publish directory가 설정되어 있습니다. 별도 설치, 빌드, 환경 변수, API 키가 필요하지 않습니다.

## 배포 없이 확인
압축을 푼 뒤 `public/index.html`을 크롬이나 엣지로 엽니다.
로컬 파일 주소와 배포한 사이트 주소는 저장 공간이 서로 다르므로, 연습 뽑기가 배포 사이트에 반영되지 않습니다.

## 운영 범위와 저장
이 버전은 **한 대의 키오스크 PC, 한 개의 브라우저 탭**에서 순서대로 사용하는 용도입니다.
학생들이 각자 휴대폰으로 접속하면 기기마다 별개의 뽑기판이 생성됩니다. 여러 기기가 공유하는 실시간 뽑기판이 아닙니다.
브라우저 데이터 삭제, 시크릿 창 종료, 다른 브라우저 사용, 사이트 주소 변경 시 기존 진행 상황이 이어지지 않습니다.
저장 기능을 사용할 수 없는 경우 화면 아래에 안내가 표시됩니다.
‘새 뽑기판’ 버튼을 누르고 확인하면 기존 결과를 지우고 다시 섞습니다. 초기화 버튼에 관리자 인증은 없습니다.
실제 키오스크 기기에서 시작하기 전에 새 뽑기판으로 초기화하세요.
티켓 등수는 브라우저에 저장됩니다. 유료 판매나 부정행위 방지가 필요한 추첨에는 서버 검증 및 관리자 인증이 필요합니다.

## 수정 위치
- 사이트 제목과 안내: `public/index.html`
- 색상과 모양: `public/style.css`
- 등수 수량: `public/script.js` 상단 `COUNTS` (합계 100장 유지)

이치방쿠지의 티켓 선택·개봉 흐름을 참고한 독립적인 디자인입니다. 로고나 이미지 자산을 복제하지 않았습니다.
